## What Was Fixed

### Issue #43: TLS Renegotiation Panic (Confirmed No-Op in v0.0.24)

**Symptom**: Process crash with panic `sessionController.onEnterLoadSessionCheck failed: session is set and locked` when foxhound-serp-scraper enrich stage processes concurrent requests against TLS-1.2-renegotiating servers.

**Production impact (v0.0.26)**: 3-5 panics per hour, restart cascades, uptime degraded.

**v0.0.24 attempted fix**: Set `session.ModifyConfig` to force `utls.RenegotiateNever`. **This had zero effect** because azuretls applies `ApplyPreset` after `ModifyConfig`, and `RenegotiationInfoExtension.writeToUConn` overwrites the config value with the Firefox preset's hardcoded `RenegotiateOnceAsClient`.

**v0.0.27 real fix**: Wrap `session.GetClientHelloSpec` in `NewStealth` to set every `RenegotiationInfoExtension.Renegotiation` in the returned spec to `RenegotiateNever`. This value survives `ApplyPreset` because it's read directly from the extension. Covers all three azuretls dial paths (connection.go, pinner.go, proxy.go). Fingerprint unchanged (wire-verified, JA3 identical).

## Root Cause Lessons (Documented in gotchas.md)

The v0.0.24 no-op teaches critical debugging patterns for concurrency/TLS bugs:

1. **Find the last writer**: Don't assume the first mutation succeeds. Trace all code paths that read/write the field. Here: `ModifyConfig` writes `config.Renegotiation`, but `ApplyPreset` → `RenegotiationInfoExtension.writeToUConn` writes it again, clobbering the first change.

2. **Test the real path, not the isolated mechanism**: The v0.0.24 test exercised `ModifyConfig` on a bare `&utls.Config{}` and never ran `ApplyPreset`. It proved `ModifyConfig` executes, not that it survives the full pipeline. Real test must include `ApplyPreset` (here: `GetClientHelloSpec` wrapper is tested alongside `NewStealth` → `dialTLS` → `ApplyPreset`).

3. **Panics in library goroutines cannot be `recover()`'d**: The panic fires in fhttp's `(*persistConn).readLoop`, which is library-spawned. Foxhound cannot add `recover()` there. Prevention must be at the config level before the handshake, not at the catch level after the crash.
